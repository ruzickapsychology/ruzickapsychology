# SEO-18-04 — Header inquiry action

## Ask and decision

The audit requests a “Book a free consult” button in the global header. The scoped Ready task instead requires a clear, availability-aware path to `/contact`, without promising online booking or a free appointment.

Implement the scoped request: a visible button improves discovery of the existing inquiry path. Disagree with literal booking wording because the destination is an inquiry form, not an appointment scheduler.

## Implementation

- Replace the desktop Contact navigation link with the shared tracked `CtaLink` button. Add the same action to the mobile primary menu.
- Read the existing normalized practice availability: **Send an inquiry** when accepting, **Join the waitlist** when waitlisting, **Current availability** when closed. All three link to `/contact`; missing site settings use neutral **Contact**.
- Keep the mobile Existing Client Portal separate and unchanged.
- Preserve the `consultation_cta_click` event without sending form contents or client data.
- Extend shared `Button`, `buttonVariants`, and `CtaLink` with a compact size (44px minimum target). Expose the existing inverse focus tone through `CtaLink` for image-backed headers. No separate header button styling system.
- Move desktop navigation to 1024px so the full wordmark and longest action label fit. Preserve menu focus trapping, Escape behavior, inert background, and resize cleanup. Document the shared size, tone, and header breakpoint in the design system.

## Validation

`npx vitest run tests/unit/site-header.dom.test.tsx` — 8 tests passed, including all three availability labels, correct contact destination, distinct portal, analytics, modal keyboard interaction, scroll contrast state, and breakpoint cleanup. jsdom emits its expected unsupported document-navigation notice when the contact link is clicked.

Updated the existing browser checks to exercise the new 1024px desktop breakpoint. Integrated CSS declarations, production build, browser layout/accessibility checks and screenshots are coordinated by the parent agent; they are not claimed complete by this report.

## Review captures

Capture the desktop header on both the image-backed homepage and solid About page, plus an open mobile menu. Verify 390/768px menu layouts and 1024/1440px desktop layouts. Unit tests cover alternate availability states because the preview uses the published CMS availability.

## Proposed disposition

Implemented on the shared branch; mark Done only after integrated verification passes. Not deployed. No claim of measured conversion improvement and no practice-owner input needed.
