# SEO-21-01 — Phone access in consultation blocks

## Ask and decision

The original audit asks for telephone access in the header, footer, homepage, and every end-of-page CTA. The accepted ticket narrows this to existing shared consultation blocks. This is justified: visitors can already call from Contact/footer, but those who reach a consultation block otherwise have to navigate away to find the number. Additional header or blanket page CTAs are unnecessary for this ticket.

## Implemented scope

- `CtaSection` accepts the existing CMS phone number and renders a secondary button-styled telephone link alongside its primary inquiry action.
- Reuses `ActionGroup`, `buttonVariants`, and `TrackedExternalLink`; no new styles, tokens, layout system, or CMS fields.
- Uses the displayed CMS number, strips formatting only for the `tel:` destination, and emits the existing `phone_click` event once with no payload.
- Passes the number through Home, About, Pricing, Specialties, Service, Blog article, and FAQ modules. FAQ's route fetches settings alongside FAQ content; page modules remain render-only.
- The phone option appears only when the consultation action exists, so closed-state CTA suppression is preserved. A missing number leaves the primary action intact.

## Integration follow-up

FAQ previously used static consultation copy regardless of availability. The new phone action must not expand that inconsistency. FAQ now receives site settings and uses the existing `getAvailabilityCtaContent` helper: accepting shows the CMS CTA and phone, waitlist uses the approved waitlist copy, closed shows the closed notice with neither action, and missing settings do not imply availability. `tests/unit/faq-consultation.test.tsx` verifies these four cases; all four passed.
