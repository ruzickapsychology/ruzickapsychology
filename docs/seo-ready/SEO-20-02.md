# SEO-20-02 — Measure image-backed contrast

## Decision

Complete the bounded measurement task with a demonstrated homepage hero fix. Do not describe this as a sitewide WCAG conformance certification. The Contact image overlay does not need darkening. Preserve follow-up findings below for separately scoped work.

## Implemented

Added `ImmersivePageHeader readability="dark"`, backed by the shared `--color-image-dark-wash` theme token (55% existing quote-overlay ink). The homepage opts into it. The wash sits between the image and content and retains the existing photograph, layout, typography and palette. The design-system document explains its use and the need to remeasure changed photographs.

The homepage hero CTA also uses the existing `CtaLink tone="inverse"` treatment for a light keyboard-focus outline on dark imagery. This reuses the shared component rather than adding a route-specific focus style.

## Measurement — 2026-10-17

Compared public `https://www.ruzickapsychology.com` against the integrated local production build at `http://127.0.0.1:3108`, Chromium at 390 × 844 and 1440 × 1000, device scale 1, reduced motion. Waited for webfonts and images. Captured actual rendered screenshots, then temporarily removed text fill, text shadows and underlines while preserving layout and backgrounds. Sampled background pixels across each text-node line rectangle and computed WCAG relative luminance against the computed foreground. Values below are the lowest ratio anywhere in those rectangles, not averages. Removing underlines avoids misclassifying underline pixels as background. SVG text is excluded from this HTML-text calculation because it uses `fill` rather than CSS `color`.

This is deliberately conservative: a line rectangle includes whitespace between glyphs. It is useful for establishing a safe lower bound, but a failing isolated texture pixel needs closer glyph-level investigation. The hero failures cover broad bright photographic areas and are visibly reproducible; they are not isolated grain speckles.

Axe `color-contrast` found zero automatic violations in all four local route/viewport combinations, but returned incomplete image-background checks. Those automatic passes do not replace the pixel measurements. Desktop and mobile hero screenshots were also visually inspected for crop and legibility.

## Follow-up findings to scope separately

- **Text over the repeating paper texture:** conservative minimum-pixel sampling found body/link regions below 4.5 (for example mobile specialties body 2.83 at a dark speckle, local location paragraph 3.36; Contact location supporting text 3.07). This differs from the broad photographic hero failure. Scope a glyph-level review of the shared paper texture and supporting-copy opacity, then evaluate a shared texture wash if warranted. Do not indiscriminately darken every text color or claim the entire page now passes AA.
- **Footer profile-link opacity:** existing profile text combines an 80% light color and 65% parent opacity; measured minimum 4.25. Scope a shared footer opacity correction and verify its whole hierarchy. This is outside the image-backed hero/Contact deliverable and should remain explicit follow-up work, not disappear behind the completed diagnostic.
- Native input values, all possible validation/error messages, every other route, other browser engines, and future CMS photograph changes were not exhaustively measured here. Existing e2e coverage remains useful but is not a blanket contrast certification.
