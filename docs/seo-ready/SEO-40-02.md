# SEO-40-02 — Performance measurement

## Ask and decision

**Done as a diagnostic.** Establish reproducible mobile and desktop measurements for home, contact, a service and an article. Do not infer field Core Web Vitals from Lighthouse scores or optimize merely to hit an arbitrary score.

The published site performs well on desktop. Home and contact mobile LCP are the clearest investigation candidates. No speculative production code changes were made for this ticket; bounded follow-ups below require controlled experiments before promotion to Ready. This task required no Christina input.

## Method

Measured the published `https://www.ruzickapsychology.com` on October 17, 2026, approximately 3:54–3:58 p.m. America/New_York. These are **pre-merge production baseline** results, not results for this PR's changed code. Coordinator release checks assess the integrated branch separately.

- Lighthouse 12.6.1; headless Chrome 155 on macOS; Node 22.22.2.
- Sequential fresh CLI browser runs; two per route/device. A third contact mobile run investigated its variation. Other agents paused CPU-heavy tests/builds during measurement.
- Lighthouse default simulated mobile: 412 × 823, DPR 1.75, 150 ms RTT, 1,638.4 Kbps throughput, 4× CPU slowdown.
- Desktop preset: 1350 × 940, DPR 1, 40 ms RTT, 10,240 Kbps throughput, 1× CPU.
- Browser storage reset by Lighthouse; actual CDN state and network conditions were not controlled. Two samples are a baseline range, not a statistical guarantee.
- No forms submitted; no reports uploaded to a public Lighthouse service.

Reproduce from the repository root, with an installed Chrome discoverable by Lighthouse (or set `CHROME_PATH`):

```sh
node scripts/measure-seo-performance.mjs https://www.ruzickapsychology.com /tmp/ruzicka-performance
```

This runs 16 audits and writes full per-run Lighthouse JSON files to the requested directory. The additional contact repeat used the same CLI defaults. Compact checked-in evidence, including timestamps, settings, per-run metrics, LCP nodes/breakdowns and image findings: [performance-baseline.json](./performance-baseline.json). Full original JSON is local in `/private/tmp/seo-performance/production/`; it is not required for the summary evidence to remain readable.

## Evidence-based follow-ups

### PERF-01 — Investigate mobile home image LCP (Backlog)

Home's floral hero is the LCP. First mobile run splits 3.50 s into approximately 646 ms TTFB, 1,194 ms load delay, 1,332 ms image load and 324 ms render delay. Lighthouse confirms it is already eagerly loaded, high-priority and discoverable in initial HTML. Existing Sanity loader already uses responsive widths, quality and format negotiation.

**Scope:** inspect the hero request chain, selected image dimensions/transfer bytes and mobile crop; compare a carefully compressed or appropriately sized variant using the existing image system. Do not blindly add more priority hints or replace the image system.

**Acceptance before shipping:** visual equivalence on mobile/desktop plus at least three matched before/after mobile runs with lower median LCP; no CLS increase or desktop regression. Report actual byte/timing improvement, not an assumed score target.

### PERF-02 — Investigate shared texture and contact LCP (Backlog)

Contact mobile LCP varies 3.10–3.91 s. Lighthouse identifies the texture-backed header section; first run attributes approximately 1,975 ms to render delay and flags image discovery/priority. The shared `/images/bg-texture.jpg` transfers approximately 79.6 KB; Lighthouse estimates roughly 11.4 KB compression savings on all measured routes. This is an experiment lead, not proof that adding preload improves the page.

**Scope:** measure a visually matched modern-format/smaller decorative texture through the existing shared theme/background system; inspect the actual contact rendering dependency before deciding whether a preload is justified. Preserve the grain aesthetic and avoid route-specific style workarounds.

**Acceptance before shipping:** matched screenshot review; three-run contact mobile median LCP improvement; reduced texture transfer; no regression on home/service/article or added unnecessary high-priority request competition.

### PERF-03 — Audit noncritical image bytes (Backlog, lower priority)

Home's first mobile run estimates 67 KB compression savings for a 116 KB Sanity image and 15 KB savings for a 640 px square image displayed at 282 px. These are not the measured hero LCP asset. Investigate actual responsive sizing and image quality through shared primitives before changing anything. Accept only visually equivalent reductions with measured transfer savings; do not claim they fix LCP without demonstrating it.

## Pushback / limits

Do not promise Lighthouse 95 everywhere. Scores vary and the measured mobile bottleneck is mainly LCP; blanket JavaScript rewrites, indiscriminate preloads, or removing analytics are not supported by the low TBT results. A full page cache/CDN test matrix, field CWV monitoring, and production after-deploy rerun remain separate work. Keep the above experiments in backlog until their scope is selected, rather than expanding this completed measurement task indefinitely.
